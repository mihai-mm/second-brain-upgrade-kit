# Module 07 - Project index and ordered archive

Installs capability 10.

## What it's for

The agent finds a project document in one or two reads, and the raw material (calls, documents received) stays separate from what was produced.

## Why it works

- **The index is a map.** Without it, the agent lists folders and opens files to understand what they are. With the index it reads one page and knows where to go.
- **The agent keeps it up to date.** An index kept by hand falls behind within a week. The rule is: whoever creates a file adds the line.
- **Three fixed places.** What was said (calls, meetings), what was received, what was produced. The same in every project, so the agent doesn't have to learn them each time.
- **Over time it is an asset.** Transcripts, materials and work ordered by project are what makes it possible, months later, to ask "what did we get wrong the last time we did something like this?".

## Essential

1. One index file per project, with a recognizable name, listing all the files grouped by type, with a one-line description each.
2. Whoever creates a file in the project adds the line to the index in the same session.
3. Raw material is kept separate from produced work.
4. No loose files in the project root.
5. Folders are born when they are needed: no empty folders created in advance.

## Adaptable

- The names. Mihai uses `calls`, `materials`, `reports` and names the index after the project folder.
- The number of places: three is the useful minimum.
- If the person already has a README or a map per project, that is the index: it only needs to be kept up to date.
- In a retrieval knowledge base the equivalent is metadata: which project a record belongs to, what type it is, where it comes from. If they are already there, this capability is present.

## How to install it

1. On the trial project, list the files and compare them with the index, if there is one. Tell the person how many files are not indexed.
2. If the index is missing, propose creating it from `templates/project-index.md`, filled in with the files that already exist. Don't move anything.
3. If the files are scattered, don't reorder them: propose the structure for future files, and leave it to the person to choose whether to move the old ones. If they say yes, they do it themselves, or you do it one file at a time with their yes for each.
4. Add the rule to the project's instructions: whoever creates a file adds the line to the index.
5. Note it in `progress.md`.

## Check

1. In a fresh session, ask the agent to find a specific document of the project: it must start from the index.
2. Have it create a new file in the project: at the end of the work the line must appear in the index without you asking.

## To roll back

Delete the index file created and remove the rule from the instructions.
