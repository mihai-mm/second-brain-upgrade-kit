# Routing questions

Where does a new piece of information go? Follow the questions in order and stop at the first answer. Adapt the destinations to the person's folders.

## 1. Is it about one client or project, or does it hold across projects?

- One client or project: go to 2.
- Across projects: go to 3.

## 2. Is it a decision, insight or number about the work, or a lasting profile of the client?

- Decision, insight or number about the work: the project's decisions file, with date and reason.
- Lasting profile (industry, tools they use, ways of working, constraints): the client's profile, in the on-demand tier.
- Where the work stands or what is next: not here. It goes in the work log, "Current state" section.

## 3. Is it about how the agent should behave, or about the world (tools, facts)?

- How the agent behaves: a line in the always-loaded index, with a detail file.
- The world: go to 4.

## 4. Is it a method that held up on real work, or a single reference?

- A method validated at least twice, useful across clients: a pattern or tool file in the on-demand tier. Leave in the project only the decision that led to it.
- A single reference (a limit, a version, a one-off trick): a line in the index with a detail file.
- Several single references on the same theme: consolidate them in one on-demand file and leave one stub pointer.

## 5. Is it a rule that belongs to one skill?

- Yes: in that skill's file, not in memory.
- No: it stays where questions 1 to 4 sent it.

## 6. Is it about who the person is (role, stable preferences)?

- Deep and lasting: the owner profile.
- A recurring working preference: a line in the always-loaded index.

## Before writing

- Does it already exist somewhere? Update that one instead of adding another.
- Is it a choice for this case only? Then it is not a rule: keep it in the log.
- Is it the agent's reading of the person? Propose it in chat. Save it only after the person confirms.
- Does the write touch the person's system? Show it first and wait for a yes.
