# Resuming a project

Rebuild the state before proposing or doing the next step.

## Where I read

<!-- To be filled in during installation with the real paths. -->

- Projects: `[projects folder]`
- A project's log: `[project folder]/[log folder]/[YYYY-Wnn].md`
- Decisions: `[project folder]/[decisions file]`
- Index: `[project folder]/[index file]`

## 1. Find the project

From context. If there is more than one candidate and the choice changes the work, ask which.

Read the project's instructions, if there are any, before anything else.

## 2. Rebuild the state

1. Find the log file of the most recent week by looking at the **name**, not the modification date.
2. Read the current state section and note the date of its last update.
3. Read the most recent entries below the state. Compare them with the state: if the entries say something the state doesn't report, or contradict it, that is a discrepancy.
4. In the decisions file read only the ones that concern the work being resumed. Ignore the ones marked as superseded.
5. If there is a task list or an open work plan for that project, look at it and compare it with the log.

If a source is missing, use the ones that exist and state the limit. Don't create files to "put things in order": flag it and that's all.

A log that has been still for weeks doesn't prove the project is idle: work may have happened without closing the session. Look at the date of the most recently modified files in the project and, if it is more recent than the log, say so.

## 3. Answer

In this order:

- **Where we are**: three or four lines.
- **Source and date**: the file the state comes from and the date of its last update.
- **Discrepancies**, if any.
- **What we are waiting for and from whom**, if anything.

Then:

- if the person already said what they want to do and the sources agree, carry on;
- if they only asked for the state, stop here;
- if they want to resume but there is more than one possible way forward, lay the options out and ask for one choice;
- if a discrepancy changes the work to be done, ask one precise question before touching anything.

## Final check

- I chose the week by file name.
- I cited source and date.
- I didn't use a superseded decision as valid.
- I didn't conclude the project is closed just because I see no recent activity.
